\section*{1. Objective}

The objective of this experiment is to systematically study the effect of
weight initialization, regularization, optimization algorithms, CNN
hyperparameters, transfer learning, fine-tuning and cross-validation on
image classification performance.

The experiment uses a single CNN architecture, MobileNetV2, and the
Oxford-IIIT Pet dataset. Students will analyze the effect of individual
design choices using training/validation curves and finally select a
suitable configuration using 5-fold cross-validation.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section*{2. Learning Outcomes}

After completing this experiment, students will be able to:

\begin{itemize}
\item explain different weight initialization strategies;
\item identify and analyze overfitting using training and validation curves;
\item compare SGD, Momentum, RMSProp and Adam;
\item explain CNN hyperparameters such as kernel size, stride, padding and pooling;
\item understand Batch Normalization and Dropout;
\item perform transfer learning and fine-tuning using MobileNetV2;
\item tune important training hyperparameters;
\item apply 5-fold cross-validation for model selection; and
\item justify the final model using accuracy, variability and computational cost.
\end{itemize}

\section*{7. Batch Normalization}

Batch Normalization normalizes activations within a mini-batch during
training.

For a mini-batch

\[
x_1,x_2,\ldots,x_m,
\]

the batch mean is

\[
\mu_B=\frac{1}{m}\sum_{i=1}^{m}x_i
\]

and the batch variance is

\[
\sigma_B^2=
\frac{1}{m}\sum_{i=1}^{m}(x_i-\mu_B)^2.
\]

The normalized activation is

\[
\hat{x}_i=
\frac{x_i-\mu_B}
{\sqrt{\sigma_B^2+\epsilon}}.
\]

The final output is

\[
y_i=\gamma\hat{x}_i+\beta,
\]

where $\gamma$ and $\beta$ are learnable parameters.

\subsection*{Numerical Example}

Consider

\[
x=[2,4,6,8].
\]

The mean is

\[
\mu_B=\frac{2+4+6+8}{4}=5.
\]

The variance is

\[
\sigma_B^2=
\frac{(2-5)^2+(4-5)^2+(6-5)^2+(8-5)^2}{4}
=5.
\]

Therefore,

\[
\sqrt{5}\approx2.236.
\]

Ignoring the very small $\epsilon$,

\[
\hat{x}_1=\frac{2-5}{2.236}\approx-1.342,
\]

\[
\hat{x}_2=\frac{4-5}{2.236}\approx-0.447,
\]

\[
\hat{x}_3=\frac{6-5}{2.236}\approx0.447,
\]

\[
\hat{x}_4=\frac{8-5}{2.236}\approx1.342.
\]

Hence,

\[
\boxed{
\hat{x}\approx[-1.342,-0.447,0.447,1.342]
}
\]

If $\gamma=1$ and $\beta=0$, these are the final outputs.

\textbf{Inference:} Batch Normalization produces approximately
zero-centred and unit-scaled activations for this mini-batch. The
learnable $\gamma$ and $\beta$ allow the network to learn an appropriate
scale and shift.

\item Y-axis: Validation Accuracy (\%)

\begin{figure}[H]

For CNN concepts, students should also understand:

\begin{itemize}
\item kernel/filter;
\item stride;
\item padding;
\item pooling;
\item number of channels; and
\item depthwise separable convolution.
\end{itemize}

For a convolution operation, the output dimension can be calculated as

\[
O=
\left\lfloor
\frac{N+2P-K}{S}
\right\rfloor+1,
\]

where $N$ is input size, $K$ is kernel size, $P$ is padding and $S$ is
stride.

\textbf{Numerical check:} For $N=224$, $K=3$, $P=1$, $S=1$ (a
``same''-padded $3\times3$ convolution), $O=224$, i.e.\ the spatial size
is preserved. For $N=224$, $K=3$, $P=0$, $S=2$ (a typical MobileNetV2
stem convolution), $O=\left\lfloor\frac{224-3}{2}\right\rfloor+1=111$.

\textbf{Experimental rule:} During a controlled hyperparameter study,
change one hyperparameter at a time while keeping the remaining settings
fixed.

\textbf{Discussion:} Explain why fine-tuning normally requires a smaller
learning rate than training a newly initialized classifier.

Because the unfrozen base layers already hold well-optimized
ImageNet-pretrained weights, a large learning rate would apply large
gradient updates that quickly destroy this useful representation
(``catastrophic forgetting''). A small learning rate ($10^{-5}$ here,
versus $10^{-3}$ for the freshly initialized head) allows the pretrained
weights to be adjusted only slightly, adapting them to the new dataset
while preserving the general visual features already learned.

classifier head (as done for Plot 11, where feature extraction is run
first) rather than unfreezing layers from the very first epoch.

\section*{11. K-Fold Cross-Validation}

After the individual studies, select 3--4 promising configurations.

Use 5-fold cross-validation on the training data.

For $K=5$,

\[
\bar{A}=
\frac{1}{5}\sum_{i=1}^{5}A_i
\]

and

\[
SD=
\sqrt{
\frac{1}{5}
\sum_{i=1}^{5}(A_i-\bar{A})^2
}.
\]

Report the result as

\[
\boxed{\bar{A}\pm SD}.
\]

The independent test set must not be used during hyperparameter selection.

\section*{15. Discussion Questions}

\begin{enumerate}

\item \textbf{What is the difference between model parameters and hyperparameters?}
Parameters (e.g.\ convolution kernel weights, Dense-layer weights and
biases, $\gamma$/$\beta$ in BatchNorm) are learned automatically from
data during training via gradient descent. Hyperparameters (e.g.\
learning rate, batch size, dropout rate, choice of optimizer, number of
epochs) are set by the practitioner before training and control how
learning happens; they are typically chosen using a validation set or
cross-validation, as in Sections 9 and 11.

\item \textbf{Why is weight initialization important?}
The starting point of gradient descent strongly affects whether and how
fast the network converges. Poor initialization can cause vanishing or
exploding activations/gradients, slow convergence, or (as seen with
Zero initialization) prevent learning altogether.

\item \textbf{Why can zero initialization be problematic for neural networks?}
If all weights in a layer start at zero, every neuron computes the same
output and receives the same gradient during backpropagation, so all
neurons stay identical throughout training (symmetry is never broken).
This was confirmed experimentally in Section 5: the Zero-initialized
model's training loss stayed pinned near $\ln(37)\approx3.61$ and
validation accuracy near random-guess level ($\sim$2--3\%).

\item \textbf{Compare Xavier and He initialization.}
Xavier/Glorot initialization scales weights based on the number of
input and output units of a layer and is derived assuming a linear or
tanh/sigmoid activation. He initialization scales weights using only
the number of input units, with a larger variance suited to ReLU
activations (which zero out roughly half their inputs). In this
experiment both performed similarly well (99.05\% vs.\ 98.91\% best
validation accuracy) since the head is shallow and sits atop a strong
pretrained backbone, but He is generally the theoretically preferred
choice here because the head's hidden Dense layer uses ReLU activation.

\item \textbf{How can training and validation curves be used to identify overfitting?}
Overfitting is indicated when training accuracy keeps rising (or
training loss keeps falling) while validation accuracy plateaus or
falls (or validation loss starts rising). In Section 6, none of the
four regularization configurations showed strong overfitting within 12
epochs; Dropout in fact showed a large \emph{negative} gap because
dropout is inactive during validation, making the model look better on
validation data than on training data.

\item \textbf{How does Dropout reduce overfitting?}
During training, Dropout randomly deactivates a fraction of neurons in
a layer on each forward pass, forcing the remaining neurons to not
rely on any single co-adapted feature detector. This acts as an
implicit ensemble of many thinned sub-networks and reduces the
network's tendency to memorize training-specific patterns.

\item \textbf{What is the purpose of Batch Normalization?}
Batch Normalization normalizes each layer's activations to zero mean
and unit variance within a mini-batch (then rescales with learnable
$\gamma$, $\beta$), reducing internal covariate shift. This stabilizes
and accelerates training, often allows higher learning rates, and can
provide a mild regularization effect. In Section 7 (Plot 5), the
BatchNorm configuration converged fastest and reached the highest
validation accuracy (99.86\%) of all four regularization strategies.

\item \textbf{Explain the numerical Batch Normalization example.}
For the mini-batch $x=[2,4,6,8]$: the mean is
$\mu_B=(2+4+6+8)/4=5$; the variance is
$\sigma_B^2=\frac{(2-5)^2+(4-5)^2+(6-5)^2+(8-5)^2}{4}=5$, so
$\sqrt{\sigma_B^2}\approx2.236$. Normalizing each value gives
$\hat{x}\approx[-1.342,-0.447,0.447,1.342]$, which has (approximately)
zero mean and unit variance. With $\gamma=1,\beta=0$ the output $y$
equals $\hat{x}$ exactly.

\item \textbf{What are the roles of $\gamma$ and $\beta$?}
$\gamma$ and $\beta$ are learnable per-channel scale and shift
parameters applied after normalization ($y_i=\gamma\hat{x}_i+\beta$).
They let the network undo or adjust the fixed zero-mean/unit-variance
normalization if that is not optimal for a given layer, so BatchNorm
does not needlessly restrict the representational power of the network.

\item \textbf{Compare SGD, Momentum, RMSProp and Adam.}
Plain SGD uses a fixed step size in the raw gradient direction and
converged slowest in Section 8 (61.55\% best val.\ accuracy in 10
epochs). Momentum accumulates a running average of past gradients to
damp oscillations and accelerate progress along consistent directions
(93.61\%). RMSProp adapts the effective learning rate per parameter
using a running average of squared gradients, converging much faster
(98.51\%). Adam combines momentum and RMSProp-style per-parameter
adaptive scaling, giving the best result here (99.05\%) with fast,
stable convergence.

\item \textbf{What happens when the learning rate is too large?}
Gradient steps overshoot the loss minimum, causing unstable, oscillating
or diverging training loss, and the model may fail to converge at all
(similar in spirit to the Zero-init non-convergence, though caused by
a different mechanism).

\item \textbf{What happens when the learning rate is too small?}
Convergence becomes very slow, requiring many more epochs to reach a
good solution, and training may appear to plateau prematurely within a
fixed epoch budget. This was observed directly in Section 9: lr
$=10^{-4}$ reached only 89.13\% best validation accuracy in 8 epochs vs.\
97.69\% for lr $=10^{-3}$, and the fine-tuning sweep showed the same
pattern (lr $=10^{-5}$ reaching only 64.40\% vs.\ 95.38\% for
lr $=10^{-4}$ in the same 8 epochs).

\item \textbf{What is the effect of increasing batch size?}
Larger batches give a smoother, lower-variance estimate of the gradient
per step but fewer weight updates per epoch and higher memory usage.
In Section 9, batch sizes 16, 32 and 64 all reached similarly high
validation accuracy (98.23\%, 98.78\%, 98.51\% respectively), with 32
giving the best result in this run -- a reasonable trade-off between
gradient stability and update frequency for this dataset size.

\item \textbf{Explain stride and padding.}
Stride is the step size (in pixels) by which the convolution kernel
moves across the input; a stride of 2 roughly halves each spatial
dimension of the output, reducing computation and increasing receptive
field. Padding adds extra border pixels (usually zeros) around the
input so that the kernel can be applied at/near the edges and, with
appropriate padding, so that the output size matches the input size
(``same'' padding), as verified numerically for $N=224,K=3,P=1,S=1$
giving $O=224$.

\item \textbf{Why is MobileNetV2 computationally efficient?}
MobileNetV2 replaces standard convolutions with depthwise separable
convolutions (a depthwise spatial convolution followed by a pointwise
$1\times1$ convolution), which drastically reduces the number of
multiply-accumulate operations and parameters compared to a standard
convolution with the same receptive field. It further uses inverted
residual blocks with linear bottlenecks to keep low-dimensional
representations compact while still allowing rich, expanded
intermediate features.

\item \textbf{What is depthwise separable convolution?}
It factorizes a standard convolution into two steps: (1) a depthwise
convolution, which applies a single spatial filter independently to
each input channel, and (2) a pointwise $1\times1$ convolution, which
combines the depthwise outputs across channels. This factorization uses
far fewer parameters and computations than a single standard
convolution that jointly filters and combines channels.

\item \textbf{What is transfer learning?}
Transfer learning reuses a model (or its learned features) trained on
one large, general dataset (here, MobileNetV2 pretrained on ImageNet)
as the starting point for a new, related task (classifying pet breeds),
rather than training a model from randomly initialized weights on the
smaller target dataset alone.

\item \textbf{Differentiate feature extraction and fine-tuning.}
In feature extraction (Case A, Section 10), the pretrained convolutional
base is frozen entirely and only a new classification head is trained
on top of its fixed features. In fine-tuning (Case B), some of the
upper base layers are unfrozen and trained jointly with the head, using
a much smaller learning rate, allowing the pretrained features
themselves to adapt to the new task.

\item \textbf{Why is a smaller learning rate generally used during fine-tuning?}
The unfrozen pretrained weights already encode useful, well-optimized
representations; large gradient updates would destroy this knowledge
(catastrophic forgetting). A small learning rate ($10^{-5}$ in Section
10's Case B, versus $10^{-3}$ for training the head alone) allows subtle
adaptation of these weights to the new dataset without erasing what was
already learned -- consistent with the sweep in Section 10c, where
$10^{-4}$ (95.38\%) converged faster than $10^{-5}$ (64.40\%) but a very
small rate is still often preferred over a longer training run to avoid
disturbing the pretrained features too aggressively.

\item \textbf{Why is K-Fold Cross-Validation useful for hyperparameter selection?}
It trains and evaluates each configuration on $K$ different train/validation
splits of the same data, giving both a mean performance estimate and a
measure of variability (standard deviation) instead of a single,
potentially lucky or unlucky train/validation split. This produces a
more reliable basis for choosing between configurations, as shown in
Section 11 where C2 was selected using both its mean (90.09\%) and its
SD (2.14) across five folds.

\item \textbf{Why must the test set remain untouched during tuning?}
If the test set influences any hyperparameter or model-selection
decision (directly or indirectly), the reported test performance becomes
an optimistic, biased estimate of real-world generalization, since the
model selection itself has effectively ``seen'' the test data. Keeping
it untouched until the single final evaluation (Section 12) gives an
honest estimate of how the final model will perform on new, unseen data.

\item \textbf{Why should mean and standard deviation both be reported?}
The mean summarizes typical performance, while the standard deviation
summarizes how consistent that performance is across folds/runs. Two
configurations can have similar means but very different reliability;
for example, C3 (Dropout 0.5) had a similar mean to C1/C2 but a
noticeably higher SD (2.59 vs.\ 2.01/2.14), indicating less consistent
behaviour across folds.

\item \textbf{Is the highest validation accuracy always sufficient to select a model?}
No. A single-run validation accuracy can be optimistic or noisy (e.g.\
the fine-tuned model's 99.73\% or the best-optimizer run's 99.05\% in
this lab, both single runs without cross-validation), and does not by
itself capture variability across data splits, generalization to a
truly held-out test set, or computational cost. As done in Section 13,
the final model should be chosen using cross-validated mean and SD, an
independent test-set evaluation, and practical considerations such as
training time and number of parameters.

\end{enumerate}
